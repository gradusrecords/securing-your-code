# Личный кабинет ZAYA — запуск на Cloudflare

Кабинет работает на Cloudflare Pages Functions (папка `functions/` в корне репозитория), база — D1,
вход — по номеру телефона с кодом из Telegram-бота. Роли: модель / клиент (определяются по заявкам) и менеджер
(по номеру из `MANAGER_PHONES`). Интерфейс: `site/cabinet.html`, кнопка «Войти» в шапке сайта.

## Что нужно сделать один раз

1. **Telegram-бот.** В Telegram откройте @BotFather → `/newbot` → имя `ZAYA`, username например `zaya_uz_bot`.
   BotFather пришлёт токен вида `123456789:AA…`. Токен никому не отправляйте и не публикуйте.
2. **База D1.** Cloudflare → Workers & Pages → проект `zaya` → Settings → Bindings (или Functions) → Add → D1 database →
   Create new → имя `zaya-cabinet`, variable name **`DB`**. Таблицы создаются сами при первом обращении.
3. **Фото (по желанию).** Если хотите хранить фото в R2 (нужна привязанная банковская карта у Cloudflare): R2 → Create bucket
   `zaya-photos` → привязать к проекту как **`BUCKET`**. Без R2 фото хранятся в D1 (браузер сжимает их до ~0,5 МБ).
4. **Секреты и переменные.** Settings → Variables and secrets (Production):
   - Secret `BOT_TOKEN` — токен от BotFather
   - Secret `TG_SECRET` — любая случайная строка 32+ символа (латиница и цифры)
   - Secret `PEPPER` — ещё одна случайная строка 32+ символа
   - Variable `BOT_USERNAME` — username бота без `@`
   - Variable `MANAGER_PHONES` — телефоны менеджеров цифрами через запятую, например `998901112233,998935556677`
   - Variable `FORM_URL` — не обязательно (адрес Google Apps Script; по умолчанию стоит рабочий)
   - Settings → Runtime → Compatibility date: `2024-09-23` или новее
5. **Передеплой.** Deployments → последний деплой → Retry (привязки применяются только к новым деплоям).
6. **Webhook бота.** Откройте в браузере `https://zaya.uz/api/tg/setup?key=ВАШ_TG_SECRET`. Ответ должен содержать `"ok":true`.
   Это делается один раз (и после смены `TG_SECRET`).

## Код заявки: подтягиваем данные из Google Таблицы

Человек вводит в кабинете код заявки (`Z-XXXXX` из колонки «Заявка №» листа `Info`; `B-XXXXX` для брифа). Сервер читает эту строку
из таблицы через Apps Script и создаёт/обновляет заявку в кабинете: анкета, контакты, замеры, направления, статус («Отбор» → этап в кабинете),
пустые поля профиля заполняются сами. Таблица остаётся источником правды: статус меняется в таблице и сам подтягивается в кабинет
(при входе и раз в 2 минуты). Настройка (один раз): `apps-script/README.md`, раздел «Код заявки в личном кабинете», плюс секрет `SHEET_KEY` в Cloudflare.

- Привязать код может только тот, чей номер (подтверждённый через Telegram) совпадает с номером в заявке или с номером родителя, записанным в строке.
  Если не совпадает, человек пишет менеджеру в чате, а менеджер привязывает код вручную (в «Чатах» над перепиской).
- Один код привязывается только к одному номеру; попытки ограничены (10 в час).
- Соответствие «Отбор» → этап: Новая заявка → Заявка получена; Под вопросом / Детское направление → На рассмотрении; Контракт → Договор;
  Запас → В резерве; Нет → Отклонена. Для брифа: Новая → Заявка получена; В работе → В работе; Готово → Завершено; Отказ → Отклонена.

## Как это работает

- «Войти» → номер телефона → если номер уже привязан к Telegram, код приходит в бота; если нет, сайт даёт ссылку на бота:
  Start → «Поделиться номером» (Telegram подтверждает, что номер принадлежит этому аккаунту) → бот присылает код.
- Заявки с сайта (анкета/бриф) теперь сначала сохраняются в D1 и сразу пересылаются в Google Таблицу (как раньше).
  Если сервер кабинета недоступен, форма отправляет данные напрямую в Apps Script.
- Менеджер: после входа видит все заявки (фильтры, поиск), меняет статус (человек получает сообщение в Telegram),
  видит анкету и фото, переписывается в чате. О новых заявках и сообщениях менеджеры получают уведомления в Telegram.
- Статусы модели: Заявка получена → На рассмотрении → Кастинг → Договор → Портфолио (+ «В резерве», «Отклонена»).
  Статусы бизнеса: Заявка получена → На рассмотрении → В работе → Завершено (+ «Отклонена»).

## Безопасность (кратко)

- Код входа: 6 цифр, хранится только хэш, живёт 5 минут, 5 попыток, ограничения по телефону и IP.
- Сессия: случайный токен в cookie `HttpOnly; Secure; SameSite=Lax` (в базе только хэш), 30 дней.
- Все изменяющие запросы требуют заголовок `x-zaya` и проверку `Origin`. Webhook проверяется секретным заголовком Telegram.
- Фото: только JPEG/PNG/WebP (проверка по содержимому), до 10 штук, видит владелец и менеджеры; EXIF удаляется в браузере.
- В интерфейсе любые данные выводятся как текст (без HTML) — защита от XSS.

## Локальная проверка

`npx wrangler pages dev site --d1 DB --binding BOT_TOKEN=… TG_SECRET=… PEPPER=… BOT_USERNAME=… MANAGER_PHONES=…`
(для проверки без настоящего Telegram можно подставить `TG_API=http://127.0.0.1:8800` и свой мок).
